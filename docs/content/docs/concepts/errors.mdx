---
title: Error Handling
description: Sentinel errors in Shield, and which ones the code actually returns.
---

Shield defines sentinel errors in the root `shield` package and in `store`. All are created with `errors.New`, so check them with `errors.Is`. Many of the root sentinels are reserved for the evaluation layers and aren't returned by anything yet; the tables below say which.

## Not-found errors

The PostgreSQL, SQLite and MongoDB stores return these from `Get<Thing>` and `Get<Thing>ByName` when no row matches.

| Error | Returned by |
|-------|-------------|
| `ErrScanNotFound` | `GetScan` |
| `ErrPolicyNotFound` | `GetPolicy`, `GetPolicyByName` |
| `ErrInstinctNotFound` | `GetInstinct`, `GetInstinctByName` |
| `ErrJudgmentNotFound` | `GetJudgment`, `GetJudgmentByName` |
| `ErrAwarenessNotFound` | `GetAwareness`, `GetAwarenessByName` |
| `ErrValueNotFound` | `GetValues`, `GetValuesByName` |
| `ErrReflexNotFound` | `GetReflex`, `GetReflexByName` |
| `ErrBoundaryNotFound` | `GetBoundary`, `GetBoundaryByName` |
| `ErrProfileNotFound` | `GetProfile`, `GetProfileByName` |
| `ErrComplianceNotFound` | `GetReport` |

`ErrPIITokenNotFound` is defined but not returned: the PII load methods return whatever tokens exist.

## Dashboard store errors

The `store` package defines the errors for the scoped `store.DashboardStore` contract that the Forge dashboard uses:

| Error | Cause |
|-------|-------------|
| `store.ErrScope` | Tenant or app missing from the `store.Scope`, or an invalid policy scope |
| `store.ErrNotFound` | No row with that ID inside the scope |
| `store.ErrCollection` | Unknown collection name |
| `store.ErrConflict` | An update's expected `updated_at` doesn't match (someone else saved first) |

## Defined but not returned yet

These exist for the engine and evaluation layers and aren't returned by any code today:

| Error | Intended meaning |
|-------|-------------|
| `ErrNoStore` | No store was configured on the engine |
| `ErrStoreClosed` | The store has been closed |
| `ErrMigrateFailed` | Database migration failed |
| `ErrAlreadyExists` | A resource with the same name already exists |
| `ErrInputBlocked` | Input content was blocked by a safety scan |
| `ErrOutputBlocked` | Output content was blocked by a safety scan |
| `ErrNoProfile` | No safety profile configured for the scan |
| `ErrInvalidConfig` | Invalid engine configuration |
| `ErrEncryptionKeyMissing` | PII encryption key not configured |
| `ErrInvalidState` | Invalid state transition |

A few consequences worth knowing. A duplicate name comes back as the database driver's own unique-constraint error, not `ErrAlreadyExists`. A blocked scan wouldn't be an error either: `ScanInput` and `ScanOutput` report blocking through `Result.Blocked`, and today they never block. With no store, `engine.Health` returns its own `shield: persistence is not configured` error rather than `ErrNoStore`.

## Checking errors

The built-in stores return the not-found sentinel itself and wrap every other error with a prefix such as `shield/sqlite: get scan: ...`. Use `errors.Is` either way:

```go
result, err := eng.Store().GetScan(ctx, scanID)
if errors.Is(err, shield.ErrScanNotFound) {
    // handle not found
}
```

`eng.Store()` returns `nil` when the engine has no store, so check for that first if you didn't set one.
