---
title: MongoDB Store
description: MongoDB store on grove for document-oriented deployments.
---

The `store/mongo` package implements Shield's `store.Store` interface, and the scoped `store.DashboardStore` contract the Forge dashboard uses, on the grove ORM with the MongoDB driver. It stores each subsystem in its own collection, which suits deployments that already run MongoDB.

## Usage

```go
import (
    "context"
    "log"

    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/mongodriver"
    "github.com/xraph/shield/store/mongo"
)

ctx := context.Background()

drv := mongodriver.New()
// The database name comes from the URI path, or from mongodriver.WithDatabase.
if err := drv.Open(ctx, "mongodb://localhost:27017/shield"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

s := mongo.New(db)
if err := s.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

## Collections

| Collection | Subsystem | Holds |
|------------|-----------|---------|
| `shield_instincts` | instinct | Threat detector configuration |
| `shield_awareness` | awareness | PII, topic and intent detector configuration |
| `shield_boundaries` | boundary | Deny and allow lists |
| `shield_values` | values | Ethical rule configuration |
| `shield_judgments` | judgment | Assessor and threshold configuration |
| `shield_reflexes` | reflex | Trigger and action rules |
| `shield_profiles` | profile | Safety profiles |
| `shield_scans` | scan | Scan results |
| `shield_policies` | policy | Policies, with tenant assignments in a `tenant_ids` array |
| `shield_pii_tokens` | pii | PII tokens (placeholder, type, your encrypted value, expiry) |
| `shield_compliance_reports` | compliance | Compliance report records |

## Migrations

`Migrate` creates the indexes for every collection directly; collections are created on first write. The package also exports `mongo.Migrations`, a grove `migrate.Group` that creates each collection and its indexes, if you'd rather register it with grove's migration orchestrator yourself. `Migrate` doesn't use it.

## When to use

- Workloads where MongoDB is already the primary data store.
- Teams already running MongoDB in their infrastructure.

The store's tests skip unless you set `SHIELD_TEST_MONGO`.
