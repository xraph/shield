---
title: SQLite Store
description: SQLite store on grove for development, tests and single-node deployments.
---

The `store/sqlite` package implements Shield's `store.Store` interface, and the scoped `store.DashboardStore` contract the Forge dashboard uses, on the grove ORM with the SQLite driver. It needs no database server, which makes it the easy choice for development, tests and single-node deployments. Shield has no in-memory store, so use SQLite for tests.

## Usage

```go
import (
    "context"
    "log"

    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/sqlitedriver"
    "github.com/xraph/shield/store/sqlite"
)

ctx := context.Background()

drv := sqlitedriver.New()
if err := drv.Open(ctx, "shield.db"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

s := sqlite.New(db)
if err := s.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

Pass `":memory:"` to `drv.Open` for a store that lives only as long as the process, which suits tests.

`Migrate` runs the package's `sqlite.Migrations` group through grove's migration orchestrator.

## Tables

| Table | Subsystem | Holds |
|-------|-----------|---------|
| `shield_instincts` | instinct | Threat detector configuration |
| `shield_awareness` | awareness | PII, topic and intent detector configuration |
| `shield_boundaries` | boundary | Deny and allow lists |
| `shield_values` | values | Ethical rule configuration |
| `shield_judgments` | judgment | Assessor and threshold configuration |
| `shield_reflexes` | reflex | Trigger and action rules |
| `shield_profiles` | profile | Safety profiles |
| `shield_scans` | scan | Scan results |
| `shield_policies` | policy | Policies and their rules |
| `shield_policy_tenants` | policy | Policy-to-tenant assignments |
| `shield_pii_tokens` | pii | PII tokens (placeholder, type, your encrypted value, expiry) |
| `shield_compliance_reports` | compliance | Compliance report records |

Safety primitive and profile names are unique per `app_id`; policy names are unique per `scope_key`.

## When to use

- Development and local testing without external dependencies.
- Single-process or embedded deployments.
- CI pipelines where running PostgreSQL is impractical.
