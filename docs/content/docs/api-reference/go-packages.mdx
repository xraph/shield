---
title: Go Packages
description: Quick reference for all Shield Go packages and their public APIs.
---

All Shield packages are importable from `github.com/xraph/shield`, except `nexusguard`, which is its own module. The safety layer packages hold configuration models and store interfaces; the detectors that run them live in `instinct/detection`, `awareness/perception` and `values/principles`, and the engine runs them all.

## Core packages

### `github.com/xraph/shield`

Root package. Exports context helpers, error constants, configuration, and shared types.

| Export | Description |
|--------|-------------|
| `WithTenant(ctx, id)` | Inject tenant ID into context |
| `WithApp(ctx, id)` | Inject app ID into context |
| `TenantFromContext(ctx)` | Read tenant ID from context |
| `AppFromContext(ctx)` | Read app ID from context |
| `Config` | Engine configuration struct, see [Configuration](/docs/concepts/configuration) |
| `DefaultConfig()` | Returns default Config values |
| `DefaultMaxScanBytes`, `DefaultProfileCacheTTL`, `DefaultJudgeTimeout`, `DefaultJudgeConcurrency` | The defaults behind zero config values |
| `Option`, `Options`, `WithProfile(...)` and friends | Top-level options that nothing in Shield consumes |
| `Entity` | Base type with timestamps |
| `Version` | Current library version |
| `ErrTenantRequired`, `ErrTenantMismatch`, `ErrNoProfile`, `ErrProfileInvalid`, `ErrInputTooLarge`, `ErrInvalidInput`, `ErrScanNotFound`, ... | Sentinel errors, see [Errors](/docs/concepts/errors) |

### `github.com/xraph/shield/engine`

The scan entry points and the layers. See [Evaluation](/docs/concepts/evaluation).

| Export | Description |
|--------|-------------|
| `New(...Option) (*Engine, error)` | Create an engine |
| `Engine.ScanInput(ctx, *scan.Input) (*scan.Result, error)` | Evaluate text going into a model |
| `Engine.ScanOutput(ctx, *scan.Input) (*scan.Result, error)` | Evaluate text going out |
| `Engine.ScanToolCall(ctx, *scan.ToolCallInput) (*scan.Result, error)` | Evaluate a proposed tool call: `allow`, `block` or `require_approval` |
| `Engine.Capabilities() Capabilities` | What this engine runs: `Persistence`, `Evaluation` and `ToolCalls` (true), `ModelJudge`, `ReportGeneration` and `ConfigWrite` (false), `Layers` (empty) and `Supported` |
| `Engine.InvalidateProfiles(tenantID)`, `Engine.InvalidateAllProfiles()` | Drop cached profiles after writing rows outside the admin service |
| `Engine.ProfileGeneration(tenantID) uint64` | Changes on every invalidation; key your own verdict cache on it |
| `Engine.Config() shield.Config` | The effective configuration, defaults filled in |
| `Engine.Store() store.Store` | The store, or `nil` |
| `Engine.Health(ctx) error` | Pings the store; errors when there's none |
| `Engine.Stop(ctx) error` | Emits `OnShutdown` to plugins |
| `WithStore(s)` | Set composite store |
| `WithPlugin(p)` | Register lifecycle plugin |
| `WithConfig(cfg)` | Set engine configuration |
| `WithJudge(j)` | Register the model judge, called only with `Config.ModelJudge` |
| `WithLogger(l)` | Set a go-utils `log.Logger`; plugin hook errors go to it too |
| `WithMetrics(m)` | Record `shield_scans_completed_total`, `shield_scan_duration_seconds` and `shield_plugin_hooks_failed_total` on a go-utils `metrics.Metrics` |
| `ScansCompletedMetric`, `ScanDurationMetric`, `ScanDurationBuckets` | The metric names and histogram bounds |
| `MaxArgumentDepth` (32), `MaxProfilePatterns` (256), `MaxRateThreshold` (100000) | Limits on tool-call nesting, operator patterns per profile and `on_rate` thresholds |
| `ActionGlob(entry)` | Split an action boundary entry into its glob and whether it matches the risk class |

### `github.com/xraph/shield/scan`

Scan input/output types, findings, and results.

| Export | Description |
|--------|-------------|
| `Input` | Content to scan, with `Profile`, `Source` and `Untrusted` |
| `ToolCallInput` | A proposed tool call: `Tool`, `Arguments`, `RiskClass`, `Metadata`, `Profile` |
| `Result` | Complete scan output, with `Reason()`, `HasPII()` and `HasFindings()` |
| `Finding` | Individual detection from a safety layer |
| `Direction` | `input`, `output` or `tool_call` |
| `Decision` | `allow`, `flag`, `redact`, `require_approval` or `block` |
| `Stricter(a, b)` | The more restrictive of two decisions; unknown counts as `block` |
| `ActionDecision(action)`, `ToolCallActionDecision(action)` | The decision a finding's action asks for on a text scan or a tool call |
| `Quote(source, text)`, `QuoteTag` | Wrap untrusted text in an `untrusted_content` tag |
| `RiskUnknown` | The risk class of a tool call that names none |
| `Stats`, `StatsFilter`, `ListFilter` | Statistics and list filters |
| `Store` | Scan persistence interface |

## Safety layer packages

### `github.com/xraph/shield/instinct`

Threat detector configuration. Categories: injection, exfiltration, manipulation, jailbreak.

| Export | Description |
|--------|-------------|
| `Instinct` | Entity with strategies, sensitivity, and action |
| `ActionBlock`, `ActionFlag`, `ActionAlert`, `ActionRedact`, `ActionQuote` | Instinct actions |
| `Category` | Injection, Exfiltration, Manipulation, Jailbreak |
| `Sensitivity` | Paranoid, Cautious, Balanced, Relaxed, Permissive |
| `Strategy` | Detection strategy with name, weight, config |
| `Store` | CRUD persistence interface |

### `github.com/xraph/shield/awareness`

Perception layer configuration: PII, secret, topic, sentiment, intent and language detectors.

| Export | Description |
|--------|-------------|
| `Awareness` | Entity with focus, detectors, and action |
| `Focus` | PII, Secrets, Topic, Sentiment, Intent, Language, Custom |
| `Detector` | Named detector with patterns and config |
| `PIIAction` | Redact, Flag, Block, Vault (`vault` redacts and stores no token) |
| `Store` | CRUD persistence interface |

### `github.com/xraph/shield/boundary`

Hard safety limits: deny and allow lists.

| Export | Description |
|--------|-------------|
| `Boundary` | Entity with limits and canned response |
| `Scope` | Topic, Action, Data, Output, Custom |
| `Limit` | Deny/allow list with scope |
| `Store` | CRUD persistence interface |

### `github.com/xraph/shield/values`

Ethical rule configuration: toxicity, brand safety, honesty, respect, safety, privacy.

| Export | Description |
|--------|-------------|
| `Values` | Entity with rules, severity, and action |
| `Principle` | Toxicity, BrandSafety, Honesty, Respect, Safety, Privacy, Custom |
| `Rule` | Principle with threshold, categories, guidelines |
| `Store` | CRUD persistence interface |

### `github.com/xraph/shield/judgment`

Contextual assessment configuration: grounding, relevance, consistency, compliance.

| Export | Description |
|--------|-------------|
| `Judgment` | Entity with domain, assessors, threshold, action |
| `RiskLevel` | None, Low, Medium, High, Critical |
| `Domain` | Grounding, Relevance, Consistency, Compliance, Custom |
| `Assessor` | Named assessor with weight and config |
| `Judge`, `JudgeRequest`, `JudgeVerdict` | The model judge interface. The request text is always redacted |
| `Store` | CRUD persistence interface |

### `github.com/xraph/shield/reflex`

Condition-action rules: triggers and actions such as block, throttle and escalate.

| Export | Description |
|--------|-------------|
| `Reflex` | Entity with triggers, actions, priority |
| `TriggerType` | `TriggerOnScore`, `TriggerOnFinding`, `TriggerOnPattern`, `TriggerOnContext`, `TriggerOnRate`, `TriggerAlways` |
| `ActionType` | `ActionBlock`, `ActionRedact`, `ActionFlag`, `ActionRewrite`, `ActionEscalate`, `ActionLog`, `ActionThrottle` |
| `Trigger` | Trigger definition with type, pattern, threshold |
| `Action` | Action definition with type, target, value, fallback |
| `Store` | CRUD persistence interface |

## Composition packages

### `github.com/xraph/shield/profile`

`SafetyProfile` composes all six safety primitives into a reusable, named bundle.

| Export | Description |
|--------|-------------|
| `SafetyProfile` | Composition entity |
| `InstinctAssignment` | Instinct with sensitivity override |
| `JudgmentAssignment` | Judgment with threshold override |
| `AwarenessAssignment` | Awareness detector assignment |
| `Store` | CRUD persistence interface |

### `github.com/xraph/shield/policy`

Administrative governance: ordered rules scoped to an app or org.

| Export | Description |
|--------|-------------|
| `Policy` | Entity with scope, rules |
| `ScopeLevel` | App or Org |
| `Rule` | CheckType + Condition + Action |
| `ParseCondition(s)`, `Condition` | Parse `finding`, `pii_detected`, `secret_detected` or `score <op> <n>` |
| `Store` | CRUD + AssignToTenant/UnassignFromTenant |

### `github.com/xraph/shield/pii`

PII token storage. Shield stores the `EncryptedValue` bytes you give it and doesn't encrypt anything itself.

| Export | Description |
|--------|-------------|
| `Token` | PII placeholder, type, encrypted value and optional expiry |
| `Stats` | Vault statistics by type and tenant |
| `Store` | Store/Load/Delete/Purge tokens |

### `github.com/xraph/shield/compliance`

Compliance report records for the EU AI Act, NIST AI RMF and SOC 2. Shield stores reports; it doesn't generate them.

| Export | Description |
|--------|-------------|
| `Report` | Compliance report record |
| `Framework` | `FrameworkEUAIAct`, `FrameworkNIST`, `FrameworkSOC2` |
| `Store` | Create/Get/List reports |

## Plugin packages

### `github.com/xraph/shield/plugin`

The `Plugin` base interface, `Registry` (with `NewRegistry`, `SetLogger` and `SetMetrics`), `HooksFailedMetric` and all lifecycle hook interfaces: `ScanStarted`, `ScanCompleted`, `ScanBlocked`, `ScanFailed`, `InstinctTriggered`, `AwarenessDetected`, `JudgmentAssessed`, `ValueViolated`, `ReflexFired`, `BoundaryEnforced`, `PIIDetected`, `PIIRedacted`, `PolicyEvaluated`, `SafetyProfileResolved`, `Shutdown`. The engine emits all of them.

### `github.com/xraph/shield/observability`

Deprecated. `MetricsExtension` implements no hooks and records nothing; use `engine.WithMetrics`. Its exported counter fields (`ScanStartedCount` and the rest) and its `On*` hook methods were removed in v1.8.0, so code that read them no longer compiles. Code that only builds and registers the plugin still does.

```go
func NewMetricsExtension() *MetricsExtension
func NewMetricsExtensionWithFactory(factory gu.MetricFactory) *MetricsExtension
```

### `github.com/xraph/shield/audit_hook`

The package name is `audithook`.

```go
func New(r Recorder, opts ...Option) *Extension
func WithActions(actions ...string) Option
func WithLogger(l log.Logger) Option // github.com/xraph/go-utils/log

type Recorder interface {
    Record(ctx context.Context, event *AuditEvent) error
}
type RecorderFunc func(ctx context.Context, event *AuditEvent) error
```

It also exports the `Action*`, `Resource*`, `Category*`, `Severity*` and `Outcome*` constants.

## ID package

### `github.com/xraph/shield/id`

```go
func New(prefix Prefix) ID
func NewScanID() ID
func NewPolicyID() ID
func NewInstinctID() ID
func NewJudgmentID() ID
func NewAwarenessID() ID
func NewValueID() ID
func NewReflexID() ID
func NewBoundaryID() ID
func NewSafetyProfileID() ID
// ... plus NewFindingID, NewPIITokenID, NewComplianceReportID, NewCheckID
// ... and a Parse* function for each type
func Parse(s string) (ID, error)
func ParseWithPrefix(s string, expected Prefix) (ID, error)
func ParseAny(s string) (ID, error)
```

`ScanID`, `PolicyID`, `InstinctID` and the other typed names are aliases of `ID`, so the compiler doesn't stop you mixing them up; the prefix does at parse time. All IDs implement `String() string` and are based on TypeID (UUIDv7, K-sortable). See [Identity](/docs/concepts/identity).

## Infrastructure packages

| Package | Purpose |
|---------|---------|
| `store` | Composite `Store` interface, the tenant helpers (`Tenant`, `ScopeVisible`, `ScopeLevels`, `ScopeWritable`, `ReportScope`, `ReportLevels`), plus the scoped `DashboardStore`, `AssignmentStore`, `PrivacyStore` and `PrivacyStatsStore` contracts and their errors (`ErrScope`, `ErrNotFound`, `ErrCollection`, `ErrConflict`, `ErrReadOnly`) |
| `store/postgres`, `store/sqlite`, `store/mongo` | Store backends: `New(db *grove.DB) *Store` and a `Migrations` group |
| `store/storetest` | Shared conformance suite: `Run(t, factory)` |
| `admin` | Validation and permission checks for dashboard operations (`Service`, `Actor`, `Audit`) |
| `extension` | Forge extension: `New(...Option) *Extension`, `Config`, `DefaultConfig()` and the `With*` options |
| `extension/contract` | The `shield` dashboard contributor: `Register`, `ResolveActor`, `ActorResolver` |
