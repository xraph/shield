---
title: Custom Plugins
description: Build plugins that react to Shield lifecycle events with audit trails, alerts or custom logic.
---

Shield uses an opt-in plugin system. Implement the `plugin.Plugin` base interface and any combination of 15 lifecycle hook interfaces to receive only the events you care about.

Only three hooks fire today: `OnScanStarted`, `OnScanCompleted` and `OnShutdown`. The evaluation layers aren't implemented, so nothing triggers an instinct, detects PII, evaluates a policy, resolves a profile or fails a scan, and no scan is ever blocked. The other twelve interfaces are defined so your plugin is ready when those events exist.

## The base interface

Every plugin must implement `Name`:

```go
import "github.com/xraph/shield/plugin"

type MyPlugin struct{}

func (p *MyPlugin) Name() string { return "my-plugin" }
```

## Opting into lifecycle hooks

Implement any subset of the hook interfaces. The registry only dispatches events to plugins that implement the relevant interface.

```go
// Receive scan completion events
func (p *MyPlugin) OnScanCompleted(
    ctx context.Context,
    scanID id.ScanID,
    decision string,
    findingCount int,
    elapsed time.Duration,
) error {
    log.Printf("scan %s completed: %s (%d findings, %s)",
        scanID, decision, findingCount, elapsed)
    return nil
}

// Receive instinct trigger events
func (p *MyPlugin) OnInstinctTriggered(
    ctx context.Context,
    scanID id.ScanID,
    instinctName string,
    score float64,
) error {
    log.Printf("instinct %s triggered (score: %.2f)", instinctName, score)
    return nil
}
```

## Available hooks

The "Fires today" column is what the engine emits now.

### Scan lifecycle

| Interface | Method | Called when | Fires today |
|-----------|--------|------------|-----|
| `plugin.ScanStarted` | `OnScanStarted(ctx, scanID, direction, text)` | A scan begins | yes |
| `plugin.ScanCompleted` | `OnScanCompleted(ctx, scanID, decision, findingCount, elapsed)` | A scan finishes | yes |
| `plugin.ScanBlocked` | `OnScanBlocked(ctx, scanID, reason)` | Content is blocked | no |
| `plugin.ScanFailed` | `OnScanFailed(ctx, scanID, err)` | A scan fails with error | no |

### Safety primitive lifecycle

None of these fire yet.

| Interface | Method | Called when |
|-----------|--------|------------|
| `plugin.InstinctTriggered` | `OnInstinctTriggered(ctx, scanID, name, score)` | Instinct fires |
| `plugin.AwarenessDetected` | `OnAwarenessDetected(ctx, scanID, detector, count)` | Awareness notices something |
| `plugin.BoundaryEnforced` | `OnBoundaryEnforced(ctx, scanID, boundary)` | Boundary blocks content |
| `plugin.ValueViolated` | `OnValueViolated(ctx, scanID, value, severity)` | Value rule violated |
| `plugin.JudgmentAssessed` | `OnJudgmentAssessed(ctx, scanID, assessor, risk, confidence)` | Judgment completes |
| `plugin.ReflexFired` | `OnReflexFired(ctx, scanID, reflex, action)` | Reflex triggers action |

### Data lifecycle

None of these fire yet.

| Interface | Method | Called when |
|-----------|--------|------------|
| `plugin.PIIDetected` | `OnPIIDetected(ctx, scanID, piiType, count)` | PII found |
| `plugin.PIIRedacted` | `OnPIIRedacted(ctx, scanID, piiType, count)` | PII redacted |
| `plugin.PolicyEvaluated` | `OnPolicyEvaluated(ctx, scanID, policy, decision)` | Policy applied |
| `plugin.SafetyProfileResolved` | `OnSafetyProfileResolved(ctx, scanID, profile)` | Profile loaded |

### System

| Interface | Method | Called when |
|-----------|--------|------------|
| `plugin.Shutdown` | `OnShutdown(ctx)` | `engine.Stop` is called (the Forge extension calls it on `Stop`) |

## Registering plugins

Register plugins when creating the engine:

```go
eng, err := engine.New(
    engine.WithPlugin(&MyPlugin{}),
)
```

Or through the Forge extension:

```go
ext := shieldext.New(
    shieldext.WithPlugin(&MyPlugin{}),
)
```

## Compile-time safety

Use compile-time interface checks to ensure your plugin implements the hooks you intend:

```go
var (
    _ plugin.Plugin            = (*MyPlugin)(nil)
    _ plugin.ScanCompleted     = (*MyPlugin)(nil)
    _ plugin.InstinctTriggered = (*MyPlugin)(nil)
)
```

If you forget to implement a method, the compiler will tell you.

## Error handling

Hook errors never reach the scan or `Stop`. The registry logs each one as a warning, with the hook and your plugin's `Name()`, and moves on to the next plugin. It uses the engine's logger, which is whatever you pass to `engine.WithLogger` (the Forge extension passes the app logger). With a metrics sink it also counts the failure on `forge_shield_plugin_hooks_failed_total{hook="..."}`, and the `run plugin hooks` span for that call is marked failed. See [Observability](/docs/guides/observability).

Each call to a hook runs inside that span, a child of the scan's span. If your plugin starts spans of its own from the `ctx` it's given, they nest there too.

A panic in a hook isn't recovered. It propagates out of `ScanInput`, `ScanOutput` or `Stop`.

## Example: Slack alerting plugin

This plugin listens for blocked scans and high-scoring instincts. Neither event fires yet, so it stays quiet until the evaluation layers land.

```go
type SlackAlertPlugin struct {
    webhookURL string
    client     *http.Client
}

func (p *SlackAlertPlugin) Name() string { return "slack-alerts" }

// Only implement the hooks you care about
func (p *SlackAlertPlugin) OnScanBlocked(
    ctx context.Context,
    scanID id.ScanID,
    reason string,
) error {
    msg := fmt.Sprintf("Shield blocked content: %s (scan: %s)", reason, scanID)
    return p.sendSlackMessage(msg)
}

func (p *SlackAlertPlugin) OnInstinctTriggered(
    ctx context.Context,
    scanID id.ScanID,
    instinctName string,
    score float64,
) error {
    if score > 0.9 {
        msg := fmt.Sprintf("High-confidence threat: %s (score: %.2f)", instinctName, score)
        return p.sendSlackMessage(msg)
    }
    return nil
}
```

## Built-in plugins

Shield ships one built-in plugin. The `observability` package still exists, but its `MetricsExtension` is deprecated and does nothing: the engine records its own metrics now (see [Observability](/docs/guides/observability)). Drop it from your plugin list.

### `audithook.Extension`

Bridges lifecycle events to an audit trail backend through a local `Recorder` interface, so the package doesn't import Chronicle. It implements every hook except shutdown, and `WithActions` limits which actions it records. The import path is `audit_hook`; the package name is `audithook`.

```go
import audithook "github.com/xraph/shield/audit_hook"

audit := audithook.New(myRecorder,
    audithook.WithActions(
        audithook.ActionScanBlocked,
        audithook.ActionPIIDetected,
    ),
)
```

`audithook.WithLogger` takes a go-utils `log.Logger`, used when the recorder returns an error.
