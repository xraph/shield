title: Custom Store
description: Implement a custom store backend for Shield persistence.
---

Every Shield subsystem defines a Go store interface, and `store.Store` composes them. Implement it to put Shield on another database. If you also want the Forge dashboard to work, implement the scoped dashboard interfaces described at the end.

## The composite store interface

```go
type Store interface {
    instinct.Store
    awareness.Store
    boundary.Store
    values.Store
    judgment.Store
    reflex.Store
    profile.Store
    scan.Store
    policy.Store
    pii.Store
    compliance.Store

    Migrate(ctx context.Context) error
    Ping(ctx context.Context) error
    Close() error
}
```

## Implementing a custom store

Your type must implement every method of every subsystem store:

```go
package mystore

import (
    "github.com/xraph/shield/store"
)

type MyStore struct {
    // your database connection fields
}

// Compile-time check.
var _ store.Store = (*MyStore)(nil)
```

Then pass it to the engine:

```go
eng, err := engine.New(engine.WithStore(&mystore.MyStore{}))
```

or to the Forge extension with `extension.WithStore`. In a Forge app, a `*grove.DB` in the container takes precedence over `WithStore` (see [Forge extension](/docs/guides/forge-extension#store-resolution)).

The engine reads a scan's profile through `ListProfiles` and the `List*` method of each primitive kind the profile names, filtered on the app and tenant, plus `GetPoliciesForScope` for the tenant's org-level and the app's app-level policies. It writes each result with `CreateScan`, and `Health` calls `Ping`. When your store also implements `store.AssignmentStore`, the engine asks it through `DashboardAssigned` which app-level policies are assigned to the tenant; without it, no app-level policy applies.

## Subsystem store interfaces

Each safety primitive defines its own store interface. The key ones:

### instinct.Store

```go
type Store interface {
    CreateInstinct(ctx context.Context, inst *Instinct) error
    GetInstinct(ctx context.Context, instID id.InstinctID) (*Instinct, error)
    GetInstinctByName(ctx context.Context, appID, name string) (*Instinct, error)
    UpdateInstinct(ctx context.Context, inst *Instinct) error
    DeleteInstinct(ctx context.Context, instID id.InstinctID) error
    ListInstincts(ctx context.Context, filter *ListFilter) ([]*Instinct, error)
}
```

### scan.Store

```go
type Store interface {
    CreateScan(ctx context.Context, result *Result) error
    GetScan(ctx context.Context, scanID id.ScanID) (*Result, error)
    ListScans(ctx context.Context, filter *ListFilter) ([]*Result, error)
    ScanStats(ctx context.Context, filter *StatsFilter) (*Stats, error)
}
```

### pii.Store

```go
type Store interface {
    StorePIITokens(ctx context.Context, tokens []*Token) error
    LoadPIITokens(ctx context.Context, tokenIDs []id.PIITokenID) ([]*Token, error)
    LoadPIITokensByScan(ctx context.Context, scanID id.ScanID) ([]*Token, error)
    DeletePIITokens(ctx context.Context, tokenIDs []id.PIITokenID) error
    DeletePIITokensByTenant(ctx context.Context, tenantID string) error
    PurgePIITokens(ctx context.Context, olderThan time.Time) (int64, error)
    PIIStats(ctx context.Context, tenantID string) (*Stats, error)
}
```

The built-in stores implement `PurgePIITokens` as "delete tokens whose `ExpiresAt` is set and before `olderThan`".

### policy.Store

```go
type Store interface {
    CreatePolicy(ctx context.Context, pol *Policy) error
    GetPolicy(ctx context.Context, polID id.PolicyID) (*Policy, error)
    GetPolicyByName(ctx context.Context, scopeKey, name string) (*Policy, error)
    UpdatePolicy(ctx context.Context, pol *Policy) error
    DeletePolicy(ctx context.Context, polID id.PolicyID) error
    ListPolicies(ctx context.Context, filter *ListFilter) ([]*Policy, error)
    GetPoliciesForScope(ctx context.Context, scopeKey string, level ScopeLevel) ([]*Policy, error)
    AssignToTenant(ctx context.Context, tenantID string, polID id.PolicyID) error
    UnassignFromTenant(ctx context.Context, tenantID string, polID id.PolicyID) error
}
```

The other subsystem stores (awareness, boundary, values, judgment, reflex and profile) follow the same CRUD pattern as `instinct.Store`. `compliance.Store` has only `CreateReport`, `GetReport` and `ListReports`.

## Dashboard support

The Forge dashboard contributor only registers when the store also implements `store.DashboardStore`:

```go
type DashboardStore interface {
    DashboardList(context.Context, Scope, string, Filter) (Page, error)
    DashboardGet(context.Context, Scope, string, string) (json.RawMessage, error)
    DashboardCreate(context.Context, Scope, string, json.RawMessage) (json.RawMessage, error)
    DashboardUpdate(context.Context, Scope, string, string, json.RawMessage) (json.RawMessage, error)
    DashboardDelete(context.Context, Scope, string, string) error
}
```

These calls are strict. Validate the `store.Scope` on every call and return `store.ErrScope` for an empty tenant or app instead of widening the query. Return `store.ErrNotFound` for a row outside the scope, and `store.ErrConflict` when an update's expected `updated_at` doesn't match. `DashboardCreate` must return `store.ErrConflict` when the name is already taken in the scope's app and tenant, so map your database's unique-constraint error to it.

Policies follow the scope's `PolicyScope()`: a tenant scope creates org-level policies keyed by its tenant, and only a scope where `AppScope()` is true (`PolicyLevel "app"`, `PolicyKey` equal to the `AppID`) touches app-level ones. A tenant scope lists and gets its own org-level policies plus the app-level policies assigned to its tenant, and an update or delete of one of those returns `store.ErrReadOnly`. `store.DashboardWritable` tells you whether a stored row is writable from a scope. Compliance reports are read from the same `PolicyScope()` only.

Policy assignment, PII token listing and retention, and PII stats come from the optional `store.AssignmentStore`, `store.PrivacyStore` and `store.PrivacyStatsStore` interfaces; without them those dashboard features report themselves unavailable.

The `store/storetest` package has a shared suite for all of this, tenancy included. `storetest.Run(t, factory)` takes a factory returning a `storetest.Backend` (the store plus all four dashboard interfaces) and runs the same checks the built-in stores pass.

## Tips

- Use compile-time interface checks: `var _ store.Store = (*MyStore)(nil)`.
- Return the subsystem's not-found sentinel (`shield.ErrScanNotFound` and so on) when a row is missing, as the built-in stores do, so `errors.Is` works for callers.
- Every `store.Store` method must follow the [store rules](/docs/concepts/multi-tenancy#the-store-rules): resolve the tenant with `store.Tenant(ctx, want)`, return the not-found sentinel for another tenant's row, and check policy and report scopes with `store.ScopeVisible`, `store.ScopeLevels`, `store.ScopeWritable`, `store.ReportScope` and `store.ReportLevels`. The engine relies on this to keep one tenant's scans away from another's rows.
- Make primitive and profile names unique per app, tenant and name, and policy names unique per scope key.
- Keep slice fields such as `Strategies`, `Detectors`, `Rules`, `Triggers` and `Actions` in JSON or JSONB columns, as the built-in SQL stores do.
